## 历史中仍存在的信息

**当前文件清理不等于历史脱敏完成。**

- 提交作者及提交者元数据仍包含真实姓名和邮箱；部分属于既有贡献者。
- 旧版本文件仍保存运营者邮箱、服务器地址、部署域名、项目引用及管理员别名。
- 历史扫描产生两个 `generic-api-key` 告警，分别位于旧前端和旧部署脚本；核对后均为
  Supabase 的 `sb_publishable_` 客户端公开 key，未发现这两个值属于 `service_role` 或 secret key。
  它们是否仍有效未通过远程调用验证。
- 即使后来改写主线，已有标签、其他引用、旧克隆或平台保留的旧对象也需要一并考虑。

因此目前不能宣称“仓库完全没有个人信息”或“可以无风险公开”。如需隐藏历史邮箱和运营信息，
下一步需要备份、重写提交内容及作者元数据、同步处理标签，再以租约保护方式强推；
这会改变提交 SHA，必须另行确认，且应保留各贡献者的署名归属。不能用删除提交记录替代真实密钥撤销。

本轮修复提交使用仓库所有者的 GitHub `noreply` 地址，本地 Git 邮箱配置也已改为该地址；
旧提交不会因此改变。其他提交工具若通过环境变量覆盖作者或提交者邮箱，仍需同步检查其配置。
