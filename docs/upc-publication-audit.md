# 源码发布：隐私清理记录

复核日期：2026-10-25。本次按仓库所有者要求清理当前文件及 main、预览标签
可达历史，保留各贡献者公开 GitHub 署名，将私人作者/提交者/标签署名改为
对应的公开署名与 noreply 地址。

## 清理范围

- 历史文件、提交消息与标签消息中的运营者邮箱、本机用户名与路径、服务器
  IP、部署域名、当前云项目引用、管理员别名均替换为示例值。
- 历史客户端公开 key、Turnstile site key、邮件 DNS 公钥与服务记录 ID 一并脱敏。
- 保留公开教师/课程目录、学校来源、测试地址、示例配置及 GitHub 仓库署名。
- 保留防止误连已退役项目的地址黑名单；该地址不是管理凭据。
- 旧历史仅保留在本机 Git 忽略目录中的私有备份，不进入源码发布包。

## 检查方法

使用 Gitleaks 8.30.1 检查完整发布历史与最终源码文件，另以已知运营标识规则
复查历史 blob、提交与标签元数据。原始扫描结果含隐私，仅保存在本地忽略目录。
发布包通过 git archive 从最终版本生成，不包含 .git、本机环境文件、数据库
备份、依赖目录或审计原始报告；压缩包另附 SHA-256 校验文件。

之前 GitHub 红叉来自发布数据校验和口径错误，不是推送失败。数据清单使用
SHA256(JSON.stringify(JSON.parse(file)))，不是文件原始字节哈希。
本机完整验证已通过 SQL 生成、TypeScript、根测试 60 项、服务测试 18 项及构建。

## 边界

没有连接真实用户数据库、验证历史配置的有效性或修改线上服务。
公开业务目录不是 Auth 用户数据，仓库不含真实用户账号、评价或数据库备份。
历史扫描曾发现的两个 key 经核对是 Supabase 客户端公开 key，仍已从历史移除。

重写历史会改变提交 SHA。已有克隆、平台缓存、旧提交链接或外部副本不会因此
自动消失；若实际密钥曾经泄露，仍须由相应服务撤销，历史重写不能代替撤销。
自动扫描也不能证明所有环境绝对安全。本次不更改仓库可见性。
