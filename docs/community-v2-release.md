# 六维评分、云端点赞与手机弹窗更新

本次内容：统一高分方向、转换已有考勤/作业分数；登录用户可点赞、取消及自赞；教师详情展示六边形雷达图；统一弹窗视口和滚动布局。`document_chunks` 不涉及。

## 数据库执行顺序

适用于已完成 P1 升级的数据库。之前的 P1 迁移和建库文件保留，不需要重跑。全新数据库先安装根目录 P1 基础脚本，再执行本次迁移。

1. 保存数据库备份。安排短暂维护窗口，暂缓评价写入。
2. 在 Supabase SQL Editor 完整运行 `supabase/dry-run-community.sql`。成功返回 `PASS: community v2 tests rolled back`，数据库改动和测试数据均不保留。该脚本会暂时锁定教师/评价表，宜低访问时执行。
3. 试运行通过后，完整运行 `supabase/migrations/20260926_community_v2.sql`，此次改动会提交。
4. 完整运行 `supabase/verify-community.sql`，成功同样返回 PASS，验收测试记录回滚。
5. 部署新版前端，并让用户刷新旧页面。确认正常提交评价、点赞/取消和签到后结束维护。

发生 SQL 错误时保留完整错误并停止后续步骤；若 SQL Editor 提示事务已中止，先运行 `ROLLBACK;`。不要删除检查语句或只执行一段 SQL。正式迁移本身以事务包裹，失败不能提交。

### 试运行报 private.swjtu_migrations 不存在

这张内部表由本次迁移创建。用户在旧版 `dry-run-community.sql` 执行时遇到 `42P01`；本地完整执行未复现，当前不能确定线上根因。新版文件首行标有 `COMMUNITY DRY RUN v2`，将 P1 检查、private schema、迁移记录表、评分转换、评分守卫、点赞存储、点赞函数和验收拆成八个阶段；依赖 SQL 在阶段运行时解析，失败保留原 SQLSTATE、DETAIL、CONTEXT 和 HINT。正式迁移也使用相同阶段顺序，改动范围不变。

在 SQL Editor 单独执行 `ROLLBACK;` 清理可能残留的失败事务，再新建查询，完整粘贴新版试运行文件。若失败，提供完整的 `Community dry-run stage`、DETAIL/CONTEXT/HINT，不要单独补建空表或继续正式迁移。试运行成功后回滚新建表是预期行为，需正式迁移后才能运行 `verify-community.sql`；验收文件对此增加了明确提示。

## 评分数据如何改变

- 六维显示名：考勤宽松度、给分宽松度、努力回报、作业轻松度、师生亲和力、教学质量。
- reviews 的考勤、作业两项：`6 - 原分数`，保留 NULL，其他四项数值不变。不是只转换已通过评价，待审/驳回也转换。
- teachers 的历史汇总两项也转换。有 approved 原始评价时按原始评价重算；没有原始评价时保留转换后的历史各项汇总，并用六项均分更新综合分，不生成假评价。
- 如果旧考勤/作业分数在 1–5 之外，迁移会停止，需核对异常数据，不会静默截断。
- 表增加 `rating_version`。完成状态记在 `private.swjtu_migrations`，重复执行不会再次反转。
- `private.swjtu_rating_backup` 保留转换前的教师/评价行供核对。该快照不替代数据库备份，也不应在出现新评价后直接覆盖恢复。
- 新前端提交 `rating_version=2` 和 `x-rating-version: 2` 请求头。旧前端在迁移后提交/修改评分会得到“刷新页面”的错误，避免方向混写。自行用 SQL 导入新评价也需明确填写 `rating_version=2`。
- 前端能识别并转换旧数据读取结果和旧缓存；新版本数据不重复反转。现有算法、排序、标签名称和示例数据一并统一。
- 数据库列名 `attendance_strictness`、`workload_difficulty` 暂时保留以减少接口改动；在版本 2 中含义分别是考勤宽松度、作业轻松度。

## 点赞数据如何保存

新增 `public.review_likes(review_id,user_id,created_at)`，其中评价 ID + 用户 ID 为联合主键。普通客户端只能读自己的记录，不能直接改记录或计数。

`public.set_review_like(评价ID, 是否点赞)` 通过登录身份和评价状态校验后更新记录。它接收明确的 true/false，因此重复请求不会重复加赞。允许给自己的已通过评价点赞；不增加积分。

旧 `reviews.likes` 计数归入新增的 `legacy_likes` 历史基数；以后新增用户点赞叠加到该基数。旧基数没有对应用户身份，不能给历史点赞猜造用户，也不能取消不属于本人的旧赞。删除用户时其新增点赞会级联删除并调整总数。

页面显示点赞中/已赞状态；失败显示错误并重新同步，结果以云端为准。刷新、切换账号或窗口重新激活会重新读取自己的点赞状态。旧示例评价不支持真实点赞。

## 界面实现

- `src/lib/ratings.ts` 集中定义六维名称、含义及版本转换。
- `RatingRadar` 使用 SVG 绘制正六边形刻度；分数越高越靠外。缺失分数标记“暂无数据”，不补高分，不把缺失点连成完整面积。仅教师详情使用，评价输入保留逐项按钮。
- `ModalFrame` 将弹窗挂载至 body，统一使用可见视口范围。顶部标题与关闭按钮不参与正文滚动，正文可滚动，长标题换行且关闭按钮保持 44px 点击区。
- 监听 VisualViewport resize/scroll，兼容地址栏与键盘引起的可用空间变化；处理安全区域、焦点返回、Escape、Tab 焦点循环和多个弹窗层级。
- 教师详情、评价、积分、登录、学院、攻略、AI 窗口及管理端共用外层框架；没有扩展 AI 业务。
