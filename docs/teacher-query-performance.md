# 教师与评价按需读取

本次只修改前端查询方式，不需要数据库迁移、重新导入 CSV 或修改已有评分。

- 首页只查询 20 位教师及教师总数，不加载全站评价。
- 教师浏览页在数据库中执行姓名、课程、完整标签、学院、学期筛选与排序，每页最多 20 位。搜索覆盖整个教师库。
- 撰写评价时只提供搜索选择，不提供翻页。未输入关键词时不请求教师列表；关键词稳定 250 毫秒后查询前 20 个匹配项，匹配较多时提示输入更完整的关键词。可通过教师详情直接带入教师。
- 课程选择只读取当前教师的课程和关键词匹配课程，不下载整份课程表。已选择的课程不会因新的搜索丢失。
- 教师详情切换到评价页签时，只读取该教师已通过审核的评价，每批 20 条。后台审核同样按状态和关键词分页，数量统计使用不返回记录正文的 HEAD 请求。
- 个人中心只读取当前账号的评价；课程推荐只读取指定课程的本学期候选教师，完整候选池用于偏好排序。
- 搜索变更会取消前一个请求；晚到的旧结果不会覆盖新结果。失败时提供重试，筛选变化会回到首批结果。

## 验证

只读验证脚本：`migration-output/20260927/verify-performance.mjs`；结果：`migration-output/20260927/performance-verification.json`。

2026-09-27（日本时间）对现有 Supabase 数据验证：

- 教师总数 2,624；首批只返回 20 位，教师请求 1 次、响应正文 26,613 字节。该次请求约 2.99 秒，包含网络与首次连接耗时，不代表整页加载时间。
- 搜索“龙文杰”返回综合分 2.0 的记录；搜索“概率论”找到 31 位教师，每批最多 20 位。
- 赵春明有 120 条旧评价，前两批各 20 条，记录不重复，保留原文、课程与教师名称。
- 特殊字符关键词不会被解释为额外筛选条件。学院筛选、课程检索、分页及空结果均通过验证。
- 当前没有本学期开课数据，开启该筛选后结果为零。
- 所有远程验证仅使用 GET/HEAD，没有写入数据库。整个验证覆盖多个独立场景，共 16 个只读请求；这不是首页请求数。

本地检查使用 `npm run lint`、`npm test`、`npm run build`。Hook 测试验证防抖、取消请求、旧响应竞态、筛选重置与重试；服务测试验证请求范围、排序和账号/教师筛选。浏览器交互尚未实测。
